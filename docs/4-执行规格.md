## 1. 项目级配置（`opencode.jsonc`，放 v2 仓库根）

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "deepseek/deepseek-v4-pro",

  // 彻底禁止子代理 —— 见 docs/2-产品规格.md 非目标第 1 条
  // 理由：opencode 没有并行子代理上限（issue #27110 仍 open），
  //       并行会打爆额度（ZCode 3009 已踩过）
  "subagent_depth": 0,

  // 大仓库快照会占满磁盘（官方已知坑），本项目不需要 UI 回滚
  "snapshot": false,

  // 长跑期间锁版本，避免中途自动更新导致行为漂移
  "autoupdate": false
}
```

> ⚠️ **待验证**：`permission` 的 schema 本轮未能从官方文档核实（`opencode.ai` 抓取受限）。
> 所以**不依赖 permission 配置做安全**，改用「AGENTS.md 规则 + 独立工作目录 + git 兜底」。
> 首次执行时若发现 `permission` 可用，再补上"禁止 `git push`、禁止读 `.env`"的硬规则。

## 2. `AGENTS.md`（v2 仓库根，提交进 Git）

> 这是 opencode 的**项目级指令文件**，每次启动自动注入。
> ⚠️ 注意：opencode **不会自动解析** AGENTS.md 里的文件引用，所以下面用明确的「读哪个文件」指令。

```markdown
# agent-stack v2 · 执行守则

## 项目性质
这是 agent-stack 的重写版（v2）。v1 在 ../agent-stack，只作对照，**不要修改它**。

## 必读文档（开工前按顺序读）
1. docs/1-接口冻结.md —— 哪些对外契约不许变
2. docs/2-产品规格.md —— 做什么、不做什么、验收标准
3. docs/3-可观测数据模型.md —— trace/span 数据契约

## 🚫 硬性禁止（违反即视为任务失败）
- **禁止修改 `agent-lite/tests/` 下的任何文件**
  测试是重写过程的回归安全网。测试失败只能改实现，不能改断言、不能 skip。
  （唯一例外：任务名明确写了「编写测试」）
- **禁止读取或修改 `.env`**（真实密钥所在）
  需要环境变量时，只参考 `.env.example`。
- **禁止执行 `git push`**。可以 `git add` / `git commit`（本地），推送由人来做。
- **禁止修改 `docs/` 下的文档**（契约由人维护）
- **禁止回退或删除 v1 目录** `../agent-stack`

## ✅ 必须遵守
- 接口变更前先查 docs/1-接口冻结.md
- 完成后运行验证命令（见任务描述），贴出真实输出
- 遇到需要做架构决策的问题 → **停下来报告**，不要自行决定
- 只做当前阶段 P0 清单里的事，**不要顺手做 P1**

## 常用命令
- 跑测试：`cd agent-lite && pytest tests/ --ignore=tests/test_eval.py -v`
  （test_eval.py 会真调 LLM，不纳入常规回归）
- Python 解释器：`D:\Miniconda3\envs\my-agent-env\python.exe`
  （⚠️ **test-env 已损坏**，解释器与标准库被删，只剩 site-packages —— 详见 LESSONS.md）
```

## 3. 阶段一执行步骤

> **原则：一个任务一次 `opencode run`。** 不要一条命令串所有任务 ——
> 阶段间要停下来给人看结果（多阶段 checkpoint 策略，见 `2-产品规格.md` 第 9 节）。

### 3.1 准备（人工，执行前完成）

```bash
cd D:/Python/janyu2cs_projects/agent-stack-v2

# 建配置与守则文件（内容见本文档第 1、2 节）
# 确认工作区干净 —— git 是唯一的"撤销"手段
git status
```

**隔离检查清单**（开工前逐条确认）：
- [ ] `.env` 不存在（只有 `.env.example`）—— 或已确认不会被读
- [ ] `gh` 的 token 权限已收窄，或本地临时禁用
- [ ] 工作区干净（所有改动已提交）
- [ ] 当前分支**不是** master（建议：`git switch -c stage1`）

### 3.2 任务 1.1 —— 修复鉴权静默失效

```bash
opencode run "读 docs/2-产品规格.md 的阶段一 P0 清单第 1.1 条并完成它。

背景：从 v1 迁移过来的 agent-lite/auth.py 读 os.getenv('API_KEY')，

2. 实现对应逻辑，使设置了 API_KEY 时，未带 Bearer token 的 /chat 返回 401
3. 运行 agent-lite/tests/test_auth.py 并贴出真实输出

禁止修改任何测试文件。完成后汇报：改了哪些文件、验证命令、真实输出。"
```

**验收**：`test_auth.py` 全绿 + 手动 curl 不带 token 返回 401。

## 4. 停机条件与续跑

| 情况 | 行为 |
|------|------|
| 任务完成且验收通过 | **停下**，向人汇报，等人确认后进入下一任务 |
| 测试失败 | **停下**，报告失败详情，**不得自行修改测试** |
| 遇到架构决策点 | **停下**，把选项与权衡写进 `QUESTIONS.md`（见下），等人答复 |
| 需要读 `.env` 才能继续 | **停下**，说明为什么需要，等人提供替代方案 |

> ⚠️ **实测发现（2026-09-23）**：opencode 本环境的 `question` 权限被自动设为 `deny` ——
> **执行者无法交互式提问**，问了也只会被拒绝。
> 所以"问人"的机制改为**写文件**：把待决问题追加到项目根的 `QUESTIONS.md`，
> 然后停下（或跳过该问题、先做不依赖它的任务）。人会在方便时答复。
> 详细格式见 `AGENTS.md` 的「怎么"问人"」一节。

**阶段一整体完成的定义**（见 `2-产品规格.md` 第 5 节）：
```bash
pytest tests/ --ignore=tests/test_eval.py -v     # 全绿
docker compose up -d && curl -s localhost:3000/health   # agent: connected
curl 不带 token 打 /chat                          # 401
grep -r "deepseek-chat" agent-lite/*.py          # 0 处（测试除外）
```

## 5. 已知坑（执行时注意）

| 坑 | 表现 | 应对 |
|---|---|---|
| Windows 支持薄弱 | 官方 super-issue #631 | 长跑前先小任务试水；本次冒烟已通过 |
| 内存占用 | 有报告 TUI 启动即占 6.5–7GB | 用 `run` 无头模式而非 TUI |
| 快照占磁盘 | 大仓库慢索引 + 大量磁盘 | 已设 `"snapshot": false` |
| 子代理无上限 | 并行打爆额度 | 已设 `"subagent_depth": 0` |
| 模型名错误 | `ProviderModelNotFoundError` | 必须 `provider/model` 格式 |
| 配置损坏 | `ProviderInitError` | 删 `%USERPROFILE%\.local\share\opencode` |
| provider 包过期 | `AI_APICallError` | 删 `%USERPROFILE%\.cache\opencode` |
